## Project Root Layout

When initialized with `crudforge init <dir>` and generated with `crudforge generate`, the project root contains:

```text
my-app/
├── config/
│   └── crudforge.config.yml      # Project configuration & generator preferences
├── gdl/
│   └── example.gdl               # Editable domain schema
├── AGENT_README.md               # Top-to-bottom agent & developer orientation
├── docs/ai/                      # AI documentation (ARCHITECTURE, ENTITIES, ROUTES)
├── .crudforge/                   # Generation state & metadata
├── .cursor/agents/               # Cursor specialist agents
├── .codex/agents/                # Codex specialist agents
├── .vscode/                      # VS Code recommendations & settings
├── public/images/logo/           # Brand logo PNG assets
├── angular.json
├── package.json
└── src/
    ├── app/
    │   ├── app.ts                # Fuse root & fuseTheme provider
    │   ├── core/
    │   │   ├── auth/             # Keycloak auth services, guards, interceptors
    │   │   └── user-management/  # IAM Users, Roles & screen matrices
    │   └── domains/admin/modules/apps/ # Generated entity modules
    └── environments/             # environment.ts & environment.prod.ts
```

## Entity Responsibility-Based Layout

Entities are organized into strict modular folders under their respective module path:

```text
book/
├── book.model.ts                         # Domain interface & types
├── book.routes.ts                        # Route definitions
├── service/
│   └── book.service.ts                   # REST client data service
├── settings/
│   └── settings.config.ts                # Field formatting & UI metadata
├── components/
│   ├── presentation/
│   │   ├── card/                         # Compact card display
│   │   ├── detail/                       # Property sheet view
│   │   └── list/                         # Paginated table view
│   ├── forms/
│   │   ├── form/                         # Reusable form component
│   │   ├── form-page/                    # Full-page route component
│   │   └── update/                       # Reactive form validation mapper
│   └── interaction/
│       ├── actions/                      # Toolbar actions & filters
│       └── filter/                       # Advanced filter drawer panel
└── shared/                               # (When entity-folder structure is selected)
```

## Centralized Shared Pack (`shared-central`)

When `output.structure: shared-central` is configured, shared logic is centralized:

```text
src/app/shared/
├── base/
│   ├── base-filter.component.ts          # Shared reactive filter base
│   ├── base-form.component.ts            # Shared form state & validation
│   ├── base-list.component.ts            # Shared pagination, export & row state
│   └── filter-types.ts                   # Filter operator definitions
├── confirmation-dialog.component.ts      # Confirmation dialog
├── resizable.directive.ts                # Table column resizing directive
└── snackbar-styles.css                   # Global toast styling
```

## Agent Documentation Pack

When `output.aiDocs.enabled: true` (default on for Fuse generation):

- Root `AGENT_README.md`
- `docs/ai/ARCHITECTURE.md`, `ENTITIES.md`, `ROUTES.md`, `UI_CONTRACTS.md`, `PRESERVATION.md`
- Pack-level `AGENT_README.md` files under `src/app/core/auth/` and `src/app/core/user-management/`

These files provide immediate context and architectural boundaries for human developers and coding agents working inside the generated repository.
